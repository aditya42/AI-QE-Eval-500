# Contributing

Contributions are welcome.

## New case requirements
A proposed record should:
1. test one primary QE capability;
2. have a realistic software-quality context;
3. include an evaluator-friendly reference;
4. include a weighted rubric totaling 1.0;
5. avoid proprietary/confidential data;
6. avoid real secrets, credentials, PII, or customer information;
7. include a clear failure category;
8. add value beyond existing cases.

## Pull request checklist
- [ ] Record validates against the schema
- [ ] Rubric weights total 1.0
- [ ] Prompt is self-contained
- [ ] Reference does not require hidden chain-of-thought
- [ ] No confidential or personal data
- [ ] Tags are meaningful
- [ ] Existing case is not duplicated
